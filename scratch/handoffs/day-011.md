- topic-01: Relevance to GCP: In Google Cloud Platform (GCP), IaaS is instantiated through Compute Engine virtual machine instances, Persistent Disk (Standard, Balanced, SSD, and Extreme block storage), and Cloud Virtual Private Cloud (VPC) networks. Google Cloud manages the physical hardware facilities, Andromeda software-defined networking mesh, and the custom Linux Kernel-based Virtual Machine (KVM) hypervisor. The tenant provisions instances using commands such as gcloud compute instances create, defines custom machine types, selects public or custom OS images, configures persistent disk attachments, and manages guest OS security updates via the OS Config agent and Patch management service.
- topic-01: Relevance to GCP: Google Cloud offers two industry-defining PaaS/CaaS services: Cloud Run and Google Kubernetes Engine (GKE). Cloud Run represents a fully managed serverless container platform built on the Knative open standard, where Google manages all cluster control planes, worker nodes, and autoscaling from zero to thousands of instances. The tenant simply provides an OCI container image and deploys with gcloud run deploy. GKE provides managed Kubernetes orchestration, where in GKE Autopilot mode, Google provisions, hardens, autoscales, and patches the worker node infrastructure and operating systems, leaving the architect to manage only Kubernetes object manifests (Deployments, Services, and Ingress).
- topic-01: Relevance to GCP: In GCP, FaaS is delivered via Cloud Run functions (formerly Cloud Functions 2nd gen). Cloud Run functions are built natively on top of Cloud Run and Google Cloud Eventarc, enabling micro-services to trigger directly on events such as Cloud Storage object creations, Pub/Sub messages, or Cloud Audit Logs. The developer writes single-purpose code blocks (Node.js, Python, Go, Java, .NET) packaged as simple functions; Google provisions the container build via Google Cloud Buildpacks, attaches HTTPS endpoints, and scales CPU and memory down to zero when idle.
- topic-01: Relevance to GCP: Google Workspace (formerly G Suite) exemplifies enterprise collaboration SaaS. In data engineering, BigQuery serves as a serverless analytical SaaS data warehouse: users execute SQL queries across petabytes of structured data without ever provisioning a server, tuning a database index, configuring a disk array, or managing a cluster. Other GCP SaaS offerings include Looker for business intelligence and Firebase authentication and app services.
- topic-01: Relevance to GCP: GCP empowers architects to mix and match service models within a single solution architecture. For example, a financial enterprise might run legacy proprietary risk-modeling software requiring customized Linux kernel tuning on Compute Engine (IaaS), host its customer-facing web API on Cloud Run (PaaS) for rapid autoscaling, process incoming audit logs asynchronously via Cloud Run functions (FaaS), and perform federated analytical reporting in BigQuery (SaaS). All tiers communicate over private Google Cloud networks using Private Service Connect and Cloud VPC Service Controls.
- topic-02: Relevance to GCP: Google Cloud guarantees security of the cloud through purpose-built server hardware, the proprietary Titan security chip (which cryptographically verifies system firmware and bootloaders via Hardware Root of Trust), and the KVM-based virtualization layer that enforces strict memory and CPU isolation between tenant VMs. Google also guarantees default encryption at rest using AES-256 for all Persistent Disks and Cloud Storage buckets, and default encryption in transit across Google's private global fiber network using MACsec and TLS. Everything configured within the project—including IAM policies, service accounts, VPC firewalls, and OS patching—remains 100% the customer's duty.
- topic-02: Relevance to GCP: In Compute Engine, Google provides the VM Manager suite (comprising OS Config, OS Patch management, and OS Inventory management) to help customers fulfill their OS patching duty, but Google does not execute patches automatically without customer policy configuration. In GKE Standard, the customer must manage node pool upgrade schedules, whereas in GKE Autopilot, Google automatically upgrades node operating systems and worker Kubernetes versions. In Cloud Run, Google manages 100% of the underlying container execution host, guaranteeing that host kernel vulnerabilities (e.g., Dirty Pipe or Spectre/Meltdown mitigations) are patched without customer intervention.
- topic-02: Relevance to GCP: In Google Cloud, customer access governance is enforced via Cloud IAM, utilizing fine-grained roles and condition-based bindings (such as restricting access by client IP or date/time). Service-to-service communication is secured via OpenID Connect (OIDC) ID tokens generated by Google Cloud's OAuth 2.0 infrastructure. Network ingress is protected by Cloud Armor security policies, which provide Layer 7 WAF inspection, DDoS mitigation, and IP allowlisting/denylisting, while VPC Service Controls establish a cryptographic security perimeter around Google APIs to eliminate data exfiltration risks.
- topic-02: Relevance to GCP: Google Cloud encrypts all customer data at rest by default using Google-owned keys. However, for complete cryptographic governance, architects use Cloud Key Management Service (Cloud KMS) to create CMEK or Customer-Supplied Encryption Keys (CSEK), enabling instant data crypto-shredding by revoking the KMS key. For data recovery, architects configure automated Persistent Disk snapshots with cross-region replication, Object Versioning and Lifecycle Management on Cloud Storage buckets, and point-in-time recovery (PITR) on Cloud SQL and Spanner databases.
- topic-02: Relevance to GCP: Google operationalizes Shared Fate through several flagship enterprise offerings: (1) Security Command Center (SCC), which continuously scans GCP projects for vulnerabilities, misconfigured IAM bindings, open firewall ports, and active malware; (2) Cloud Architecture Center Security Foundations, providing ready-to-deploy Terraform blueprints; (3) Risk Protection Program, where Google collaborates with leading cyber-insurers (such as Munich Re and Allianz) to offer specialized cyber insurance policies to customers who achieve verified security posture ratings in SCC.
