- topic-01: Relevance to GCP: Normalized schemas maximize the efficiency of Cloud SQL and AlloyDB buffer pools. Because normalized rows are narrow and compact, database engines fit more index nodes and active rows into volatile RAM (shared buffers), achieving higher cache hit ratios (> 99%) and slashing expensive disk I/O operations on Google Cloud Persistent Disks. When reporting requires denormalized views, architects use Cloud Data Fusion or BigQuery federation to transform normalized transactional schemas into dimensional star schemas optimized for analytical OLAP processing. Supported by PostgreSQL shared_buffers architecture and BigQuery external query documentation.
- topic-01: Relevance to GCP: In Google Cloud managed databases, query execution plans can be inspected using Cloud SQL Insights and PostgreSQL EXPLAIN (ANALYZE, BUFFERS). Cloud SQL Insights visualizes join performance, identifying expensive Sequential Scans caused by missing foreign key indexes. In globally distributed Cloud Spanner, architects design table interleaving (INTERLEAVE IN PARENT) to physically co-locate child order records with their parent customer rows on the same storage split, eliminating cross-network RPC latency during joins. Supported by Cloud SQL Insights and Spanner Schema Design guides.
- topic-01: Relevance to GCP: Google Cloud provides clean architectural separation between transactional and analytical processing: (1) Cloud SQL Read Replicas offload read-heavy aggregation queries; (2) BigQuery Federated Queries (EXTERNAL_QUERY) and Datastream CDC stream relational data into BigQuery for analytical processing. - topic-02: Relevance to GCP: Google Cloud guarantees full ACID transactions across its primary relational portfolio. In Google Cloud SQL and AlloyDB, ACID durability is enforced by writing transaction logs synchronously to Google Cloud high-availability persistent disks across multiple availability zones. In Google Cloud Spanner, Google achieves distributed multi-region ACID transactions with external consistency at global scale using synchronized GPS and atomic clocks (TrueTime API). Supported by Spanner paper and Cloud SQL HA documentation.
- topic-02: Relevance to GCP: WAL mechanics underpin disaster recovery and point-in-time recovery across Google Cloud databases. Supported by Cloud SQL PITR documentation.
