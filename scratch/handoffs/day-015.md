## Product-claim list

GCP relevance passages and supporting documentation sections:

- topic-01: Relevance to GCP: In Google Cloud serverless platforms—including Google Cloud Run and Cloud Functions—container instances do not possess local writeable disks for persistent log files. Cloud Run directly intercepts everything written to stdout and stderr and streams it into Google Cloud Logging. Output emitted to stdout defaults to INFO severity, whereas output sent to stderr is automatically categorized as ERROR or WARNING unless structured JSON is utilized to override the log level. Supporting section: MIT Missing Semester § Shell Scripting (Standard Streams).
- topic-01: Relevance to GCP: Google Cloud Build steps and Google Kubernetes Engine (GKE) lifecycle hooks (such as preStop and postStart handlers) evaluate container exit status. In Cloud Build, each build step executes as a container; if a step process returns a non-zero exit code, Cloud Build aborts subsequent build steps immediately, marks the build as FAILURE, and triggers Pub/Sub alerting. In GKE, if an initialization container (initContainer) exits non-zero, Kubernetes halts Pod startup and prevents defective workloads from serving user traffic. Supporting section: MIT Missing Semester § Shell Scripting (Exit codes and flow control).
- topic-01: Relevance to GCP: The Google Cloud CLI (gcloud) is designed specifically for pipeline composition. Using flags such as --format=json or --format="value(networkInterfaces[0].networkIP)" combined with jq and grep, architects can query fleet-wide resource states in single-line pipeline commands. Supporting section: MIT Missing Semester § Shell Scripting (Command pipelines).
- topic-01: Relevance to GCP: Google Cloud provides optimized platforms for each architectural style: (1) Monoliths on Compute Engine Virtual Machines; (2) Microservices on GKE; (3) Serverless workloads on Google Cloud Run and Eventarc. Supporting section: MIT Missing Semester § Shell Scripting (Process boundaries).
- topic-01: Relevance to GCP: Google Cloud enforces fault domain isolation through multiple architectural layers: (1) Resource Limits in GKE / Cloud Run; (2) Asynchronous Decoupling via Pub/Sub; (3) Project Perimeters. Supporting section: MIT Missing Semester § Shell Scripting (Process isolation).
- topic-02: Relevance to GCP: Google Cloud enables multi-layered validation architectures. At the perimeter, Google Cloud Armor inspects HTTP requests for SQLi and XSS patterns, while Google Cloud API Gateway validates OpenAPI schema definitions, terminating invalid payloads before they reach application containers. Supporting section: 12-Factor App § XI Logs (Input validation).
- topic-02: Relevance to GCP: Google Cloud's serverless and container runtimes are built expressly around Twelve-Factor contracts. Google Cloud Run and Google Kubernetes Engine (GKE) automatically capture all stdout and stderr streams from containers. Furthermore, Google Secret Manager and Cloud Run environment variable bindings implement Factor III. Supporting section: 12-Factor App § XI Logs (Treat logs as event streams).
- topic-02: Relevance to GCP: Google Cloud provides native distributed tracing via Google Cloud Trace. External Application Load Balancers and Cloud Run automatically generate and inject the X-Cloud-Trace-Context header or W3C traceparent header. When applications include the Google Cloud trace string in structured JSON log payloads under logging.googleapis.com/trace, Google Cloud Logging correlates logs with Cloud Trace spans. Supporting section: 12-Factor App § XI Logs (Event streams & distributed correlation).
- topic-02: Relevance to GCP: Google Cloud Logging provides special reserved JSON keys that govern how log entries are indexed and displayed: severity, message, logging.googleapis.com/trace, logging.googleapis.com/spanId, and jsonPayload query language. Supporting section: 12-Factor App § XI Logs (Event format).
- topic-02: Relevance to GCP: Google Cloud addresses observability risks through native tools: Cloud DLP (Sensitive Data Protection), Log Exclusion Filters, and Log Sinks to BigQuery or Cloud Storage. Supporting section: 12-Factor App § XI Logs (Event stream routing).
