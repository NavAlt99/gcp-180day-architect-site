## 5. Product-Claim List with Supporting Sections

| Product / Technology Claim | Supporting Official Section |
|---|---|
| POSIX exit code conventions: exit status 0 indicates successful execution; status 1–255 indicates failure | POSIX IEEE Std 1003.1, "Exit Status" & MIT Missing Semester § Shell Scripting |
| Bash defensive execution: `set -euo pipefail` halts execution immediately on simple command failure (`-e`), treats unset variables as errors (`-u`), and returns rightmost failure in pipelines (`-o pipefail`) | MIT Missing Semester § Shell Scripting |
| Twelve-Factor App Factor III (Config): store configuration strictly in environment variables, decoupling deployment targets from code | The Twelve-Factor App, Section III "Config" |
| Twelve-Factor App Factor VI (Processes): execute application as one or more stateless, share-nothing processes | The Twelve-Factor App, Section VI "Processes" |
| Twelve-Factor App Factor XI (Logs): treat logs as continuous unbuffered event streams written directly to `stdout` | The Twelve-Factor App, Section XI "Logs" |
| Google Cloud Logging structured ingestion: JSON payloads written to container `stdout` are parsed into `jsonPayload`, automatically indexing special fields like `logging.googleapis.com/trace` | Google Cloud Logging Documentation, "Structured logging" (`https://cloud.google.com/logging/docs/structured-logging`) |
| W3C Trace Context standard: `traceparent` header with version (`00`), 16-byte trace ID, 8-byte parent span ID, and trace flags | W3C Recommendation "Trace Context" (`https://www.w3.org/TR/trace-context/`) |
