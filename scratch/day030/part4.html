Lab 30.1: Multi-Criteria Regional Trade-Off Evaluation and Org Policy Constraint Simulation

Goal

Evaluate multi-criteria trade-offs between Google Cloud candidate regions (us-central1, us-east4, and europe-west3) across latency, pricing differentials, carbon intensity (CFE%), and compliance boundaries. Then simulate and verify how Google Cloud's Resource Locations Organization Policy constraint (constraints/gcp.resourceLocations) blocks out-of-boundary deployments.

Expected Result

A comprehensive console report quantifying the trade-offs between North American and European deployment targets, accompanied by verified policy simulation logs confirming 100% deterministic blocking of unapproved regional provisioning requests.

Mode

Hybrid (Python evaluation engine and policy enforcement simulation in scratch/day030/compare-regional-tradeoffs.py).

Preflight

  • Verify Python 3.10+ runtime environment.
  • Review candidate region parameters: primary operational hub (us-central1), disaster recovery standby (us-east4), and European expansion territory (europe-west3).
  • Ensure working directory is positioned in the repository root.

Exact Execution Steps

  1. Inspect Regional Comparison Engine: Review the trade-off evaluation script located at scratch/day030/compare-regional-tradeoffs.py to examine how pricing multipliers, latency benchmarks, and carbon scores are calculated.
  2. Execute Multi-Criteria Regional Comparison: Run the evaluation script from the repository root: 
    python3 scratch/day030/compare-regional-tradeoffs.py
  3. Analyze Regional Trade-Off Deltas: Observe the output comparing us-central1 vs europe-west3 and us-central1 vs us-east4. Verify that compute pricing variance (+12%) and transatlantic round-trip latency (+90ms) justify isolating European workloads into a dedicated local region.
  4. Verify Organization Policy Simulation: Confirm that the policy evaluation engine enforces constraints/gcp.resourceLocations with allowed_values = ['in:europe-locations'], validating that attempts to deploy Cloud SQL or Cloud Storage in us-east4 and us-central1 are rejected with HTTP 403 policy violation errors.
