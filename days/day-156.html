2. Capture supplier integration, generated content, discovery and human review: technical mechanics

Use a content state machine such as received → normalized → generated → validated → needs-review → approved/rejected → published. Keep source and derived values separate, attach a product and content version, and make reprocessing idempotent. The review UI needs role separation, diff visibility, rejection reasons and an audit record.

For discovery, define the query contract, retrieval corpus, ranking signal, inventory/price freshness and safe fallback. A conversational agent can help a user find products, but order creation and inventory claims need authoritative systems and explicit authorization. Image generation needs content-policy, brand and product-identity checks. Measure relevance and business outcomes separately from model fluency.

Acceptance rule

No generated field reaches a customer-facing channel without a valid product identity, schema validation, provenance, policy decision and a reversible publication record.

3 · Real-world problems and solutions

These deep-dive cases preserve the original case or exam reasoning while separating supplied facts from architectural inference. The incident diagrams are synthetic exercises, not observed production events.

1. Read the official Cymbal Retail case · field case

Enterprise scenario: A generated description overwrites a supplier attribute, while a later supplier correction is treated as a duplicate and discarded. Sales channels diverge and a call-center agent sees different information from the website.

Constraints: Use synthetic data, preserve the prior artifact and keep unknown behavior explicitly labeled.

Root cause: The design lacked stable product/version identities and separated neither source fields nor derived fields. Retain provenance, version updates, define conflict ownership and publish only approved catalog states. Reconcile every channel against the approved version.

Defensible remediation: The design lacked stable product/version identities and separated neither source fields nor derived fields. Retain provenance, version updates, define conflict ownership and publish only approved catalog states. Reconcile every channel against the approved version.

Verification: Re-run the bounded case, compare it with the declared acceptance signal and save the resulting decision trace.

Residual risk: Synthetic rows cannot prove supplier quality or production-scale throughput. Record the data owner and the test needed before rollout.

2. Capture supplier integration, generated content, discovery and human review · field case

Enterprise scenario: A customer asks for a product with a particular feature. Retrieval finds a similar item, but the assistant claims the item is in stock and suitable. The response came from stale catalog text rather than the inventory or product-attribute authority.

Constraints: Use synthetic data, preserve the prior artifact and keep unknown behavior explicitly labeled.

Root cause: Discovery, recommendation, inventory and order authority were conflated. Restrict retrieval to approved content, call authoritative inventory only when needed, show a safe uncertainty response and log the evidence used. Add adversarial and stale-data tests.

Defensible remediation: Discovery, recommendation, inventory and order authority were conflated. Restrict retrieval to approved content, call authoritative inventory only when needed, show a safe uncertainty response and log the evidence used. Add adversarial and stale-data tests.

Verification: Re-run the bounded case, compare it with the declared acceptance signal and save the resulting decision trace.

Residual risk: A relevance score is not a guarantee of factual correctness or conversion. Maintain human review for sensitive categories and measure returns, complaints and correction time.
