1 · Topics of the day

SSH

SSH provides an authenticated, encrypted channel to a remote host. A client can authenticate with a key, apply per-host settings from a configuration file, forward a local port through the connection, or reach a private target through a bastion (jump) host.

Why today and where it sits: Day 7 applies Day 6 process and permission evidence to controlled remote administration. SSH sits between the operator workstation, an optional bastion and the private target, with a separate host-identity and user-authentication decision at each hop.

Problem preview: An operator reaches the bastion but cannot reach the private Order API VM and responds by exposing SSH to the internet. The change enlarges the attack surface while leaving the missing jump-host path unresolved.

Technical discussion · Real-world problem · Exercise

Package managers (apt, yum/dnf)

A package manager resolves, installs, updates and removes software from configured repositories while tracking dependencies and package metadata. APT is common on Debian-derived systems; DNF and its predecessors are common on RPM-derived systems. Their package names and repository state can differ.

Why today and where it sits: VM operations require a trustworthy way to identify and change installed software after access is established. The package manager connects repository metadata and signatures to an explicit host transaction and any resulting service restart.

Problem preview: An operator refreshes repository metadata and records the Brightloaf VM as patched even though the installed library never changed. The vulnerable process remains in service and the audit evidence asserts a repair that did not occur.

Technical discussion · Real-world problem · Exercise

Shell scripting

A shell script is a file of commands interpreted by a shell. Variables hold values, loops repeat work, conditionals branch on a command's exit status, and quoting preserves a value as one argument. A useful automation script reports failure explicitly when an input is invalid.

Why today and where it sits: Shell scripting turns the day's inspection commands into repeatable controls. It sits at the automation boundary where argument expansion, command status and output streams determine whether the next deployment step may run.

Problem preview: A validator prints an error for malformed order JSON but the wrapper finishes with exit status zero. The release pipeline publishes invalid configuration and interrupts order intake.

Technical discussion · Real-world problem · Exercise

/proc virtual filesystem and process trees

The /proc filesystem exposes live kernel and process information through file-like paths. Each process has a PID directory with status, command-line and file-descriptor information. A process tree relates a child PID to its parent PID.

Why today and where it sits: /proc connects a service manager's unit view to the kernel's live process view. Parent PID, state and descriptors help identify the actual Order API worker before an operator sends a signal.

Problem preview: Several Python processes share the same command name and an operator terminates the wrong PID. An unrelated worker stops while the stalled order worker and customer backlog remain.

2 · Technical discussion of each topic

SSH

The SSH client first verifies the server's host identity, then authenticates the user and establishes an encrypted session. A private key stays with the client; the server receives proof that the client possesses it, not the private key itself. Client configuration can map a short host alias to a hostname, user, identity file and jump host. A ProxyJump setting reaches a private destination via an intermediate SSH server; it does not make the final server public. Local port forwarding binds a client-side port and carries traffic through SSH to a specified target reachable from the remote side.

In cloud environments, an architect should know which host is reachable, which identity is used at each hop and who controls the host keys. A bastion reduces direct exposure but becomes a high-value access point. Port forwarding can bypass an intended network boundary if granted carelessly. Treat a host-key warning as an identity problem to investigate, not an error to suppress. Record only host aliases and synthetic names in the lab; never commit a private key.

Package managers (apt, yum/dnf)

Package management is more than downloading an executable. A repository publishes metadata about versions, dependencies and signatures; the manager uses that metadata to choose a transaction. Refreshing package metadata does not by itself install an update. Installing or upgrading changes the VM image state and may restart services. An architect therefore needs a patch window, repository trust policy, version record and rollback plan, especially when a VM is used as a long-lived server. Cloud image updates and in-guest package updates are related but distinct responsibilities.

APT and DNF provide analogous operations but not identical syntax or version choices. A diagnostic first identifies the OS and available manager, then inspects a package before changing it. Running both managers on one host because a guide lists both would be a mistake. For this foundation day, the lab is read-only; package installation is introduced only when a later task has an approved disposable VM and cleanup plan.

Shell scripting

The shell expands variables before launching commands. Double quotes preserve spaces and wildcard characters inside a value as a single argument; omitting quotes can split a filename and change what a command receives. A loop can process multiple files, while an if statement tests a command's exit status. In Bash, zero means success and a nonzero status means failure; the status is not the command's printed output. A pipeline can hide an earlier failure unless its status behavior is understood. For architecture automation, an apparent green exit after skipped or invalid input is dangerous because later deployment steps may rely on a false artifact.

Scripts should validate inputs, print a useful error on standard error, and return a nonzero status for a failed check. Keep secrets out of source files and logs. The lab below uses synthetic JSON and validates it without installing another parser. It is a small, reproducible example of the same control needed in build and deployment pipelines.

/proc virtual filesystem and process trees

/proc is a pseudo-filesystem, not a durable log. Its entries reflect live kernel state and disappear when a process exits. A PID can later be reused, so record timestamps and process identity along with a PID when diagnosing an incident. The status file includes process state and parent PID; the file-descriptor directory shows open endpoints such as files, pipes and sockets, subject to permissions. A shell-launched child normally has the shell as its parent until process relationships change. This helps distinguish an application worker from its supervisor and track whether a leaked descriptor or orphaned child is involved.

Cloud VM troubleshooting often starts with service status and logs, then narrows to a process's PID, parent, state and open descriptors. /proc supports that inspection without changing the process, but it does not explain business correctness or replace a service's structured logs. Avoid copying full environments or command lines into study notes because they can contain credentials.

3 · Real-world problem and solution for each topic

SSH

Failure: A learner connects to the bastion but cannot reach a private VM, then opens the VM's SSH port to the entire internet to “fix” access.

Cause: The private VM was intentionally reachable only from the bastion. The client configuration lacked the jump setting or the bastion-to-VM path was blocked. Public exposure changes the security design without proving the original route.

Fix: Verify the target alias, jump host, user, key selection and authorized bastion-to-VM route. Test host identity and authentication at each hop. Repair the missing jump or narrow firewall path; remove the accidental public rule and confirm it is gone. Keep access logs and document the intended SSH path.

Constraints and evidence: keep the VM private, do not copy private keys to the bastion, preserve access logs, and record host-key fingerprints through an approved channel. Diagnose client alias expansion, each hop's authentication, and the bastion-to-target route before changing a firewall.

Verification and residual risk: expand the effective client configuration locally, authenticate through both known host identities, confirm the target has no unintended public SSH path, and retain logs. The bastion remains a privileged access point requiring hardening, patching and monitored identities.

Package managers (apt, yum/dnf)

Failure: A VM still runs a vulnerable library after an operator refreshes repository metadata and reports “patch complete.”

Cause: A metadata refresh lists candidate versions but does not install them. The operator did not inspect the installed version or execute and verify an approved update transaction.

Fix: Identify the OS and package manager, compare installed and candidate versions, apply the update under the service's change procedure, and verify the running process uses the intended version. If a restart is required, schedule and observe it. Do not claim a patch based on metadata-download output alone.

Constraints and evidence: use the host's actual package family, approved repositories and maintenance window; capture installed and candidate versions before mutation. Retain the transaction result, restart decision and post-change process version with a rollback package or image plan.

Verification and residual risk: compare installed and intended versions, inspect transaction success, restart only when required, and verify the running process mapping. A later repository change or rollback can reintroduce drift, so the evidence needs a timestamp and host identity.

Shell scripting

Failure: A deployment script prints “validated” for a malformed order fixture and the next step publishes it.

Cause: The script ran a validator but ignored its exit status, or used an unquoted filename that split into multiple arguments. The final successful print command made the script exit zero.

Fix: Quote file paths, branch on the validator's result, emit errors to standard error and exit nonzero when validation fails. Test a valid file, an invalid file and a filename containing spaces. Preserve those outputs in the review artifact before the script is used with cloud resources.

Constraints and evidence: the validator must work with spaces in paths, preserve distinct stdout and stderr semantics, and block publication when any input fails. Run valid, invalid, mixed and no-argument cases and record their exact statuses.

Verification and residual risk: require status 0 only for all-valid inputs, status 1 when any file is invalid and status 2 for missing arguments. Future commands added after validation can still mask the status unless the script preserves or exits with the recorded result.

/proc virtual filesystem and process trees

Failure: A worker appears “running,” but it no longer processes orders. An operator restarts the wrong PID because several Python processes are present.

Cause: The operator used a process name alone, without relating the PID to its parent service and open descriptors. The selected process was a different child.

Fix: Identify the service unit or supervisor, inspect its main PID and child tree, then compare the relevant process state, command identity and logs. Stop or restart only the intended disposable process under its supervisor. After recovery, verify order processing with a synthetic request rather than treating a listed PID as success.

Constraints and evidence: do not signal a PID selected only by process name, avoid copying sensitive command lines or environments, and retain a timestamp because PIDs can be reused. Correlate unit, main PID, parent-child relationship, state, descriptors and application logs.

Verification and residual risk: act through the owning supervisor, confirm the old process exited, observe the intended replacement PID and test a synthetic order. A healthy process tree still does not prove downstream dependencies or Fulfillment idempotency.

Shell scripting

Goal: Build a Bash script with a loop, conditional, quoted path and meaningful exit status. Mode: local Linux terminal with Bash and Python 3.

Expected Result: the valid file returns 0, the mixed run returns 1, and the filename containing a space remains one argument. Preflight: confirm bash and python3 are available and create only the three named synthetic files.

Step 1 — Create fixtures and the script

Open a terminal in your Day 1 repository and run: 

cd ~/gcp-architect-learning
printf '{"order_id":"demo-001"}\n' > 'day-007-valid order.json'
printf '{"order_id":\n' > day-007-invalid.json
cat > day-007-validate.sh <<'SH'
#!/usr/bin/env bash
if [ "$#" -eq 0 ]; then
  printf 'usage: %s FILE...\n' "$0" >&2
  exit 2
fi
failed=0
for path in "$@"; do
  if python3 -m json.tool "$path" >/dev/null 2>&1; then
    printf 'valid: %s\n' "$path"
  else
    printf 'invalid: %s\n' "$path" >&2
    failed=1
  fi
done
exit "$failed"
SH

The quoted argument keeps the valid filename containing a space intact. The loop checks each supplied file and remembers whether any failed.

Step 2 — Run a success and failure case 

bash day-007-validate.sh 'day-007-valid order.json'
printf 'success exit=%s\n' "$?"
bash day-007-validate.sh 'day-007-valid order.json' day-007-invalid.json
printf 'mixed exit=%s\n' "$?"

Expected: 

valid: day-007-valid order.json
success exit=0
valid: day-007-valid order.json
invalid: day-007-invalid.json
mixed exit=1

The invalid line goes to standard error, so ordering can vary if output streams are captured separately. In your note, explain why the final mixed status is 1 even though one file passed. Verification: save the script and both runs; include a no-argument check if you want to test usage status 2. Cleanup: keep the synthetic files as fixtures or remove only these three Day 7 files after recording evidence. No cloud resources exist.

Troubleshooting: capture stdout and stderr together when comparing order, and record the status immediately after each script run before another command overwrites $?. Artifact Acceptance: save the complete script, success status 0, mixed status 1, no-argument status 2, and a short explanation of "$@" quoting.

/proc virtual filesystem and process trees

Goal: Inspect a short-lived child process and its relationship to the shell. Mode: local Linux terminal; no cloud use.

Expected Result: relate the disposable child PID to the current shell, inspect its live status and descriptors, then observe its /proc directory disappear after termination. Preflight: confirm the process, text-filter, directory-listing and signal tools plus Bash job control are available.

Step 1 — Start and inspect a child

Keep the same terminal open and run: 

sleep 30 &
child_pid=$!
ps -o pid,ppid,stat,comm -p "$$" -p "$child_pid"
grep -E '^(Name|State|Pid|PPid):' "/proc/$child_pid/status"
ls -l "/proc/$child_pid/fd"

Expected: the sleep process has its own PID, its PPID normally matches your shell PID, and its status is live. Its file-descriptor list is small and machine-dependent. The process may exit before inspection on a very slow machine; start a new disposable child if needed. Do not inspect a different person's process.

Step 2 — Stop and verify cleanup 

kill -TERM "$child_pid"
wait "$child_pid"
child_status=$?
printf 'child exit=%s\n' "$child_status"
if ps -p "$child_pid" -o pid,stat,comm; then
  printf 'unexpected: child still present\n'
else
  printf 'child stopped\n'
fi

Expected: Bash commonly reports 143 for a process terminated by SIGTERM, and the final ps finds no live child. A different shell can report differently; record the actual status. In your note, relate the child PID to the parent and explain why /proc/$child_pid disappears afterward. Cleanup: the disposable sleep process is stopped; no file or cloud resource was created.

Troubleshooting: if the child exits before inspection, start a new disposable sleep 30 process and replace the captured PID; never select another process by name. Artifact Acceptance: record shell PID, child PID, PPID, state, descriptor listing, observed wait status and proof that the child no longer exists.
